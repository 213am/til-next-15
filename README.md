# Layout.tsx 의 이해

## layout.tsx

- `_app.tsx` 와 `_document.tsx` 의 역할을 모두 함
- 공통으로 적용할 내용을 작성하고, 공통으로 적용할 구조를 작성하는 곳
- `/src/app/layout.tsx` 를 **글로벌 레이아웃**이라고 함

```tsx
import type { Metadata } from "next";
import { Geist, Geist_Mono } from "next/font/google";
import "./globals.css";

const geistSans = Geist({
  variable: "--font-geist-sans",
  subsets: ["latin"],
});

const geistMono = Geist_Mono({
  variable: "--font-geist-mono",
  subsets: ["latin"],
});

export const metadata: Metadata = {
  title: "TIL Next 15",
  description: "Generated by create next app",
};

export default function RootLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <html lang="ko">
      <body className={`${geistSans.variable} ${geistMono.variable}`}>
        <div style={{ border: "5px solid yellow" }}>
          모든 페이지에 공통으로 표시될 내용입니다
        </div>
        {children}
      </body>
    </html>
  );
}
```

# React 19 - Server Component 의 이해

- React Server Component 를 줄여서 rsc 라고 합니다.
- rsc 의 사전렌더링 자료는 `rscpayload` 라고 합니다.

- React 18 버전에서 추가된 기능

  - 클라이언트용 컴포넌트와 구분
  - 서버용 컴포넌트

    - 서버에서 딱 한번만 생성
    - interaction 이 없는 컴포넌트

## react 컴포넌트의 종류

- React Server Component (RSC)

  - 실행 시 서버에서만 실행 (server에서 1번 실행)
  - 브라우저에 JS 번들 없이 HTML과 데이터만 전달
  - rscpayload라는 문자열 데이터를 생성하여 클라이언트로 보냄
  - React의 useState, useEffect 같은 클라이언트 전용 Hook 사용 불가
  - 서버에서 데이터를 직접 가져올 수 있음 (예: DB 쿼리, API 호출)
  - `client component 에서 server component 를 import 하지 않도록 노력하자`
    - 위처럼 하면 server component 가 Next 에서 client component 로 변경됨
  - 대표적인 예시: app/page.tsx 같은 Next.js의 기본 페이지 컴포넌트

<br/>

- React Client Component
  - 실행 시 서버에서 한 번 실행된 후, 클라이언트에서 다시 한 번 실행
  - 클라이언트에서 JS 번들을 로드하여 실행됨
  - 브라우저에서 동적으로 HTML을 조작할 수 있음
  - useState, useEffect 같은 클라이언트 전용 Hook 사용 가능
  - onClick 등의 이벤트 핸들러 사용 가능
  - use client 지시어를 포함해야 클라이언트 컴포넌트로 동작
  - 대표적인 예시: 버튼, 입력 폼, 애니메이션 등 인터랙티브한 UI

## 기준을 세워보자

- Next 에서는 무조건 서버 컴포넌트가 기본값
- 만약, **`use 훅`** 또는 **`이벤트 핸들러`** 를 사용해야 한다면 별도로 `"use client"` 라고 명시해야 함
- 웹브라우저에서만 실행되는 라이브러리라면 `"use client"` 라고 명시해야 함

- **굳이 사용해야 한다면**

```tsx
"use client"; // 명시가 필요
// Next App Router 에서는 기본이 server component
import { useEffect } from "react";

    console.log("컴포넌트가 웹브라우저에 보이면 실행"); // 마운트
  }, []);

  return <div className={styles.page}>인덱스 페이지</div>;
}
```

## 실습예제) 검색창 컴포넌트 만들기

- 코딩 컨벤션

  - /src/app/components 만들기

  - /src/components 만들기 **next 에서 추천하는 방식**

    ```bash
    /src
      ├── app/ (Next.js의 App Router)
      ├── components/ (전역 컴포넌트 저장)
      │   ├── SearchBar.tsx
      │   ├── Button.tsx
      │   ├── Navbar.tsx
      │   └── ...
      ├── pages/ (Pages Router 사용 시)
      ├── styles/
      ├── utils/
      └── hooks/

    ```

- 컴포넌트 파일명 규칙
  - Next.js에서는 파일명에 대한 강제적인 규칙은 없지만, 일반적으로 아래와 같이 사용됩니다.

```tsx
SearchBar.tsx → ✅ 📌 PascalCase (가장 일반적이고 추천)
search-bar.tsx → ✅ kebab-case (URL이나 CSS 클래스 네이밍에 주로 사용)
searchBar.tsx → ✅ camelCase (자바스크립트 변수/함수 네이밍에 주로 사용)
searchbar.tsx → ❌ (잘 사용되지 않음)
```

- React Hook 은 `"use client"` 적용

```tsx
"use client";
import { useState } from "react";

const SearchBar = () => {
  const [search, setSearch] = useState("");

  const searchHandler = () => {
    console.log(search);
  };

  return (
    <div>
      <input
        type="text"
        value={search}
        onChange={(e) => setSearch(e.target.value)}
      />
      <button onClick={searchHandler}>검색</button>
    </div>
  );
};
export default SearchBar;
```

- `Bundling`은 오로지 `클라이언트 컴포넌트`만 해당
  - Bundling 은 클라이언트에서 실행될 JavaScript 코드를 하나의 파일(번들)로 묶는 과정
- `Hydration` 은 오로지 `클라이언트 컴포넌트`만 해당
  - Hydration 은 서버에서 미리 렌더링된 HTML을 클라이언트에서 React와 연결하여 인터랙티브하게 만드는 과정

### 2. 동적 라우팅

```tsx
"use client";
import { useRouter } from "next/navigation"; // app router 방식
import { ChangeEvent, useState } from "react";

const SearchBar = () => {
  const [search, setSearch] = useState("");

  const onChangeSearch = (e: ChangeEvent<HTMLInputElement>) => {
    setSearch(e.target.value);
  };

  // 동적 라우팅
  const router = useRouter(); // import 주의
  const searchHandler = () => {
    router.push(`/search?keyword=${search}`);
  };

  return (
    <div>
      <input type="text" value={search} onChange={(e) => onChangeSearch(e)} />
      <button onClick={searchHandler}>검색</button>
    </div>
  );
};
export default SearchBar;
```

## 검색창 css 및 기능정리

- /src/components/searchbar.tsx

```tsx
"use client";
import { useRouter } from "next/navigation"; // app router 방식
import { ChangeEvent, KeyboardEvent, useState } from "react";
import style from "@/components/searchbar.module.css";

const SearchBar = () => {
  const [search, setSearch] = useState("");

  const onChangeSearch = (e: ChangeEvent<HTMLInputElement>) => {
    setSearch(e.target.value);
  };

  // 동적 라우팅
  const router = useRouter(); // import 주의
  const searchHandler = () => {
    if (!search) {
      return;
    }
    router.push(`/search?keyword=${search}`);
  };

  const pressEnterHandler = (e: KeyboardEvent<HTMLInputElement>) => {
    if (e.key === "Enter") {
      searchHandler();
    }
  };

  return (
    <div className={style.container}>
      <input
        type="text"
        value={search}
        onChange={(e) => onChangeSearch(e)}
        onKeyDown={(e) => pressEnterHandler(e)}
      />
      <button onClick={searchHandler}>검색</button>
    </div>
  );
};
export default SearchBar;
```
